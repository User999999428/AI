# 2단계: 눈 감김 감지의 원리

보고서에 그대로 옮겨 쓸 수 있도록 정리한 설명입니다.

## 1. 한 줄 요약

얼굴 랜드마크에서 **눈의 세로 길이 ÷ 가로 길이**(EAR)를 계산합니다.
이 값이 기준보다 작으면 "눈을 감았다"고 판단합니다.
**감은 상태가 1.5초 이상 이어지면 "졸음"**으로 판단해 경고합니다.

## 2. 눈 위의 점 6개

MediaPipe는 얼굴에서 점 478개를 찾습니다. 그중 눈 하나마다 6개를 골라 씁니다.

```
          p2        p3                 p1, p4 : 눈의 양 끝 (눈꼬리, 눈머리)
    p1                    p4           p2, p3 : 위 눈꺼풀
          p6        p5                 p6, p5 : 아래 눈꺼풀
```

| 점 | 화면 왼쪽 눈 | 화면 오른쪽 눈 |
|---|---|---|
| p1 (끝) | 33 | 362 |
| p2 (위) | 160 | 385 |
| p3 (위) | 158 | 387 |
| p4 (끝) | 133 | 263 |
| p5 (아래) | 153 | 373 |
| p6 (아래) | 144 | 380 |

프로그램 화면에서 노란 점으로 표시되는 것이 이 점들입니다.

## 3. EAR (Eye Aspect Ratio, 눈 종횡비) 계산

```
         |p2 - p6|  +  |p3 - p5|          ← 세로 길이 2개의 합
  EAR = ───────────────────────────
              2 × |p1 - p4|                ← 가로 길이의 2배
```

`|a - b|`는 두 점 사이의 거리입니다. 피타고라스 정리 `√(가로차² + 세로차²)`로 구합니다.

**계산 예시**: 눈 가로 길이가 30픽셀, 세로 길이가 각각 9픽셀, 8픽셀이면

```
EAR = (9 + 8) / (2 × 30) = 17 / 60 ≈ 0.28   → 눈을 뜬 상태
```

눈을 감으면 세로 길이가 1픽셀 정도로 줄어듭니다.

```
EAR = (1 + 1) / (2 × 30) = 2 / 60 ≈ 0.03   → 눈을 감은 상태
```

### 왜 '길이'가 아니라 '비율'을 쓰나?

카메라에 가까이 가면 눈이 크게 찍히고, 멀어지면 작게 찍힙니다.
세로 길이만 보면 거리에 따라 값이 달라집니다.
가로 길이로 나눈 **비율**은 거리가 바뀌어도 거의 같습니다.
그래서 앉은 자세가 조금 바뀌어도 안정적으로 판단할 수 있습니다.

### 왜 두 눈의 평균을 쓰나?

한쪽 눈이 머리카락이나 안경테에 가려 잘못 측정될 수 있습니다.
두 눈의 평균을 쓰면 그런 실수의 영향이 줄어듭니다.

## 4. 눈 감김 → 졸음 판단

1. 매 프레임(1초에 약 30번) EAR을 계산합니다.
2. **EAR < 기준값(기본 0.18)** 이면 "눈 감음"입니다.
3. 눈을 감기 시작한 시각을 기억해 두고, 계속 감고 있는 시간을 잽니다.
4. **1.5초 이상** 계속 감고 있으면 "졸음" 경고를 띄웁니다.
5. 눈을 뜨면 시간을 0으로 되돌립니다.

### 왜 시간 기준이 필요한가?

사람은 1분에 15~20번쯤 눈을 깜빡입니다. 한 번에 약 0.1~0.4초 걸립니다.
EAR만 보면 깜빡임도 "눈 감음"으로 잡힙니다.
그래서 **깜빡임보다 충분히 긴 시간(1.5초)** 동안 감고 있을 때만 졸음으로 판단합니다.

```
EAR
0.30 ─────╮  ╭──────────────╮                    ╭────
          │  │              │                    │
0.18 - - -│- │- - - - - - - │- - - - - - - - - - │- -  ← 기준값
          ╰──╯              ╰────────────────────╯
         깜빡임(0.2초)          계속 감음 (1.5초 넘으면 졸음 경고)
         → 졸음 아님
```

## 5. 정확도를 높이기 위한 처리

| 처리 | 이유 |
|---|---|
| **픽셀 좌표로 변환** | 랜드마크 좌표는 0~1 비율입니다. 화면은 가로가 더 길어서, 그대로 거리를 재면 가로 길이가 짧게 계산됩니다. 화면 크기를 곱해 실제 픽셀로 바꾼 뒤 잽니다. |
| **흔들림 줄이기 (스무딩)** | 같은 표정이어도 프레임마다 EAR이 조금씩 떨립니다. `새 EAR × 0.5 + 이전 EAR × 0.5`처럼 섞어서 숫자를 부드럽게 만듭니다. |
| **보정 (c 키)** | 눈 크기는 사람마다 다릅니다. 3초 동안 눈 뜬 EAR을 모아 **중앙값 × 0.6**을 그 사람의 기준값으로 정합니다. 중앙값(가운데 값)을 쓰는 이유는 보정 중에 눈을 깜빡여도 결과가 거의 흔들리지 않기 때문입니다. |

## 6. 사람마다 기준값이 다르다 (테스트 결과)

얼굴 사진 3장으로 눈을 뜬 상태의 EAR을 재 보았습니다.

| 사진 | 눈 뜬 EAR |
|---|---|
| 평범한 표정 A | 약 0.31 |
| 평범한 표정 B | 약 0.42 ~ 0.55 |
| 활짝 웃는 얼굴 | 약 0.20 |

모두 눈을 뜨고 있는데도 0.20부터 0.55까지 차이가 컸습니다.
특히 웃으면 눈이 가늘어져 EAR이 크게 줄었습니다.
그래서 **기준값 하나를 모든 사람에게 쓰기 어렵고, 사람별 보정이 필요하다**는 결론을 얻었습니다.
이것이 보정 기능을 만든 이유입니다.

## 7. 데이터셋으로 검증한 결과 (CEW 눈 감은 사진)

웹캠 없이 공개 데이터셋 사진으로 "눈 감은 얼굴을 얼마나 잘 잡는지" 검증했습니다.

- **데이터**: CEW(Closed Eyes In The Wild) 데이터셋의 눈 감은 얼굴 사진 1192장
  (출처·라이선스: [dataset_cew.md](dataset_cew.md))
- **방법**: 사진마다 EAR을 계산합니다. `EAR < 기준값`이면 "감음"으로 판단하고, 맞힌 비율을 셉니다.
  사용한 스크립트는 `tools/eval_ear_photos.py`입니다.
- **날짜**: 2026-11-23

### 결과

| 항목 | 값 |
|---|---|
| 얼굴을 찾은 사진 | 1192장 중 **1172장 (98.3%)**, 못 찾음 20장 |
| 감은 눈 EAR 평균 | **0.063** |
| 감은 눈 EAR 중앙값 | **0.052** |
| 감은 눈 EAR 최소 ~ 최대 | 0.006 ~ 0.249 |

| 기준값 | 감은 눈을 "감음"으로 맞힌 비율 |
|---|---|
| 0.10 | 83.9% |
| 0.12 | 90.5% |
| 0.15 | 96.1% |
| **0.18 (현재 기본값)** | **98.5%** |
| 0.20 | 99.4% |
| 0.25 이상 | 100.0% |

### 해석

1. **감은 눈의 EAR은 대부분 0.1보다 훨씬 작습니다.** 중앙값이 0.05입니다.
   눈꺼풀 위아래 점이 거의 붙는다는 EAR의 원리가 실제 사진에서도 맞았습니다.
2. **기준값이 너무 낮으면 감은 눈을 놓칩니다.** 0.10이면 감은 눈 6장 중 1장 정도(16.1%)를 놓칩니다.
   일부 사진은 눈을 감았는데도 EAR이 0.1~0.25로 나왔기 때문입니다.
   사진 화질이 낮거나 얼굴이 기울어 눈꺼풀 점이 정확히 붙지 않은 경우로 보입니다.
3. **기준값 0.18이면 감은 눈의 98.5%를 잡습니다.** 더 올려도 늘어나는 폭이 작습니다(0.20에서 +0.9%p).
4. 반대로 기준값을 너무 올리면 **눈 뜬 사람을 "감음"으로 잘못 볼 위험**이 커집니다.
   6절에서 잰 웃는 얼굴의 눈 뜬 EAR이 약 0.20이었습니다.
5. 그래서 **기본 기준값 0.18을 유지**했습니다. 감은 눈은 거의 다 잡으면서, 웃는 얼굴의 뜬 눈(약 0.20)보다는 낮은 값입니다.

### 이 검증의 한계

- **눈 뜬 사진이 없었습니다.** 그래서 "뜬 눈을 뜬 눈으로 맞힌 비율"과 전체 정확도는 계산하지 못했습니다.
  0.18이 뜬 눈을 얼마나 잘못 잡는지는 6절의 사진 3장으로만 확인했습니다.
  눈 뜬 사진 데이터로 추가 검증이 필요합니다.
- 사진 한 장씩 판단했으므로, 실제 프로그램의 "1.5초 이상 계속 감으면 졸음" 조건은 검증하지 않았습니다.
  실제 프로그램에서는 시간 조건이 있어서, 한 프레임 오판으로 바로 경고가 뜨지는 않습니다.
- 데이터셋 속 사람들 기준의 결과입니다. 사용자 본인에게는 `c` 키 보정을 함께 쓰는 것이 좋습니다.

## 8. 한계점 (오판 가능성)

| 상황 | 생길 수 있는 문제 |
|---|---|
| 고개를 숙이고 책이나 공책을 볼 때 | 눈이 아래를 향해 눈꺼풀이 내려가 EAR이 작아짐 → "감음"으로 오판할 수 있음 |
| 활짝 웃을 때 | 눈이 가늘어져 EAR이 작아짐 |
| 안경 반사, 어두운 조명 | 눈 위치를 정확히 못 잡아 값이 흔들림 |
| 고개를 옆으로 많이 돌릴 때 | 눈 가로 길이가 짧게 보여 EAR이 커짐 |

이런 한계는 3단계(얼굴 방향, 시선)와 5단계(여러 정보를 합친 집중도 점수)에서 함께 고려할 예정입니다.
